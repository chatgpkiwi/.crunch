# Update Project Workflow

Use this workflow for feature requests, bug reports, enhancements, design
changes, retries, or any other change to an existing registered project.

## 1. Establish Scope

Identify the project before inspecting or changing it. If the user names a
project, use `tools/list_projects.py` or `tools/get_project.py` to verify its
`project_id`. If the project is not clear, list the projects and ask the user
to choose.

Inspect only the information needed to understand the request:

- Use `tools/get_project_status.py` for progress and task state.
- Use `tools/get_project_summary.py` with the `project_id` and `"output":"simple"`
  for an overview.
- Use `tools/get_phase.py` or `tools/get_task.py` with both the record ID and
  `project_id` when detailed scope is needed.

## 2. Clarify and Confirm

Restate the requested outcome, affected area, and acceptance criteria. Ask a
targeted question only when an answer would materially change the work. Before
creating a new phase or task, summarize the proposed plan and obtain explicit
confirmation.

Do not silently add unrelated cleanup, redesign, or future work.

## 3. Record the Approved Work

Read `AGENTS/TASK-QUALITY.md` before creating or revising tasks.

- Add a new phase with `tools/add_phase.py` only when the change needs a
  distinct deliverable and ordering boundary.
- Add one or more new tasks with `tools/add_task.py`, including the verified
  `project_id` and the parent phase ID.
- Amend an existing task with `tools/update_task.py`, including its
  `project_id` and `task_id`.
- Retry a failed task with `tools/fix_task.py`, replacing its instructions with
  a specific corrected brief.

After each write, inspect the relevant status or record and report what is now
ready. Do not start the worker unless the user asks.

Completed-task and completed-phase summaries are generated by the worker. Do
not manually invent them when planning or revising work; ensure the task brief
instead identifies the contracts and interfaces that later work must preserve.
